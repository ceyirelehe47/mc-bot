# 03｜验收矩阵与反假成功规则

这是业务验收，不是 JSON schema。采集器和 checker 由 Agent 编写，字段由实现设计。**不得写一个只读取 `passed=true` 的 checker。**

## A. 通用证据要求

每个 LIVE 用例须关联：用例 ID、源码候选、客户端/服务端产物哈希、world/run/game-session 身份、运行配置、动作请求/终态、相关前后物理状态、计时和独立 checker 的判断理由。

证据必须可串回同一次运行。只提供脚本最后一行文字、布尔汇总或一张背包截图不足以证明执行路径。普通物品汇总也不能证明同 ID 不同组件物品没被交换。

归档经过脱敏的真实原始快照/事件和机器派生结果；raw 未净化证据留在仓库外。证据中的 server truth 是测试 oracle，不可作为运行控制器的超感知输入。

所有固定数量、次数、成功门槛是本包新规定，不是声称旧系统已经达到。所有测试不得依赖伪造 completion 或等待时间后默认成功。

## B. G1：控制与恢复（C 组）

| ID | 场景 | 硬判定 |
|---|---|---|
| C01 | 合法动作运行中，提交参数错误/不支持动作 | 原执行不被自动 cancel 或替换；新请求准确拒绝 |
| C02 | 明确取消导航、采集、GUI 各一次 | 收到取消后的控制意图停止；最终静止/空闲或明确恢复中，不再有新业务 mutation |
| C03 | 重复请求、乱序/旧控制帧 | 重复不重复扣料/产出；旧帧不影响新执行；相同 ID 不同参数拒绝 |
| C04 | mutation 前断线、mutation 后确认前断线 | 前者不产生额外效果；后者报告未知并对账，不能自动重做 |
| C05 | lease 过期或两个不同 owner 竞争 | 保持唯一 authority；无固定 owner 偷换、无双进程抢键 |
| C06 | 食物使用中、破坏中、拿起物品到 cursor 时取消 | use/attack/移动输入及导航停止；cursor 有明确可核验去向；不无意丢弃 |
| C07 | 有限批量超过旧内存执行记录阈值并重启 | 内存可回收；保留去重/未决语义，旧请求不能复活；不靠永久加大上限 |
| C08 | 正常客户端与 Bob 并存，Bob 后台/最小化 | 所有者客户端/桌面输入不受影响；Bob 可运行；无 OS 输入模拟 |

C02 的时序：用协议接收/处理记录区分“取消请求发出”“客户端处理”“回执到达”。清理应在客户端处理后不超过 10 个 client ticks 完成；网络等待另有明确有界超时。惯性/在途包造成的已有结果须归账，不能误判成承诺回滚，也不能无限容忍新指令继续执行。

C07 可以自动化为非物理轻量执行与 ledger 单测，不要求为凑数跑 1025 次挖矿。

## C. G2：导航（N 组）

预先固定 6 类场景，每类至少 3 次，同一最终候选；普通成功场景每次不超过 120 秒。fixture 大小应事前限定为局部场景，而不是用 120 秒要求任意距离。

| ID | 场景 | 硬判定 |
|---|---|---|
| N01 | 平地与一格台阶，到指定可站格 | 位置/高度真实达标；default 不改地形 |
| N02 | 两格高障碍但侧面存在通路 | 绕过而不是撞跳/挖穿；世界改动数为零 |
| N03 | U 形障碍，需要先远离最终目标 | 能完成真实绕路；不把短暂距离变大当永久失败 |
| N04 | 山坡到可交互方块的工作站位 | 站位可达、触及且 exact crosshair 命中；不是仅距离接近 |
| N05 | 外部 actor/fixture 事件在途中改变通路 | 有界重规划或准确失败；不无限重复同一计划 |
| N06 | 完全不可达且不许破坏 | 在约定预算内明确不可达/失败；没有幽灵 completed、无挖穿 |

另验：未传 terrain permission、false、true 三种请求。false/缺省必须零挖零放；true 若不支持必须拒绝，若支持必须受范围/数量约束。取消后库内部 pathing process 与按键都释放。

绕行、工作站位与控制负例通过，才算导航门通过。只证明 Baritone jar 能加载不算。

## D. G3：背包/GUI（I 组）

| ID | 场景 | 硬判定 |
|---|---|---|
| I01 | 指定工具/食物/方块分别放在主背包不同非快捷栏槽 | 真实调槽后选中正确物品；无 slot≥9→0 假映射 |
| I02 | 指定移动 1、7、31 件；有可合并与满堆 | 实际数量准确；不可移动超出保护/预留部分 |
| I03 | 两件同 ID 但组件/耐久不同的工具 | 指定/受保护对象保持正确，不靠 item ID 合计蒙混 |
| I04 | 普通箱子与木桶分别存入和取出 | 同一事务基础；准确目标/数量/库存归属；外部 screen 所有权正确 |
| I05 | 背包满、容器满、目标槽不可插入 | 明确失败或诚实部分转移；不丢物、不复制、不假成功 |
| I06 | 旧 screen、换容器、cursor 非空、重连 | stale 计划拒绝/重建；不向新屏错点；cursor 无丢失 |
| I07 | 未知角色/ghost 类型测试槽 | 只读或明确不支持，不自动当普通储物槽写入 |
| I08 | 已有 Tom’s deposit 回归 | 原所有权、数量和保留工具语义不退化；不用它替代 I04 |

只显示 can_take 不能证明 can_insert 或槽位角色；测试要覆盖“能取不能放”。

## E. G3：业务动作与假阳性负例（A 组）

| ID | 场景 | 硬判定 |
|---|---|---|
| A01 | 两种原木分别原生 2×2 合成木板/木棍/工作台 | 原生客户端路径；材料与产物/余物守恒；新增数量语义明确 |
| A02 | 放置/打开工作台，3×3 合成木镐和石镐 | exact 目标 Screen、真实材料消耗、产物真正入包 |
| A03 | 包里有工作台但没有可用工作台；或工作台在墙后/距离外 | 3×3 不得完成、不得服务端直接变换背包 |
| A04 | 已有 4 木板，再请求新增 4 木板 | 合法材料足够时真实新增；不能已有数量达标就冒充本次合成 |
| A05 | 木板/木棍不够或产物容量不足 | 不假成功；若多步已有部分效果，明确报告而不是声称原子失败零变化 |
| A06 | 请求放工作台，但快捷栏另有泥土 | 放的是工作台；目标精确；对应消耗成立 |
| A07 | 放置支撑面会导向别格；外部 actor 抢先占目标 | 不误放或诚实失败；别格方块/他人放块不得算成功 |
| A08 | 食物在主包、饥饿；另一次主包无食物/不饥饿 | 前者真实吃到指定/允许食物；后者拒绝或明确无操作 |
| A09 | 同种木头/石头多个，目标被外部移除 | 不挖最近替代对象；绑定原目标/失效事实 |
| A10 | 目标挖掉但掉落没捡到 | 不把目标消失等同材料已获得；拾取失败/部分效果可区分 |
| A11 | 取消、死亡、换世界期间的工具和 GUI 动作 | 无旧任务复活；保护物、cursor、执行状态可对账 |
| A12 | 未见墙后资源、历史缓存跨世界、禁止位置指令 | 控制器无透视目标；只读管理员查询不参与决策 |

用 spy/结构化调用追踪与独立结果快照证明 native path；检查某个类名字符串存在不构成执行路径证明。

## F. G4：核心链（B 组）

最终候选 5/5 完整连续通过，矩阵在运行前写定。建议矩阵：两个橡木场景、两个第二树种场景、一个非默认快捷栏/堆叠布局场景；初始游戏物资仍为空，布局扰动由运行中真实操作实现。

每个 fixture 的初始树和石面在已声明的局部导航范围内。默认限时每次 12 分钟，从执行器取得控制并开始首次观察计时；不得靠暂停游戏时钟达标。服务器明显卡顿要记录 client/server ticks 与 wall time，不能事后改门槛。

每次终点同时满足：
1. 原木由本次正常挖掘/拾取取得，没有中途给物。
2. 2×2 和 3×3 都经原生客户端交互完成。
3. Bob 当前真实库存拥有木镐与石镐；石镐材料来自本次木镐采石拾取。
4. 放置的工作台在精确位置，重新打开成功；cursor 为空，动作终态且无残留输入。
5. 无未经授权世界改动、无管理员决策信息、无服务端合成捷径、无未结 unknown。

有一次失败，就保存失败并修复。任何代码/配置修复后重新开始该候选的完整五次集合；之前失败仍在总尝试记录里。

## G. G5：自然场景与完整过夜（S 组）

两次自然场景均须：
- 事前声明 seed/初始条件/难度/客户端和服务端配置，Bob 从空包开始；无预给工作台、工具、食物。
- 起点附近有可通过正常感知发现的基础资源。测试场景可以事前选定，不用“资源非常远”测无界探索；不得事后换种子隐藏失败。
- 上层 LLM 通过相同语义接口规划，测试期间实现 Agent 不修改生产代码、不用管理员信息补洞。
- 正常制作基本工具、黄昏前准备避难，在线经历自然完整夜晚到清晨；无睡觉跳夜、登出躲夜、死亡重生、keepInventory、时间/天气/难度修改。
- sheltered 只能由实际可核验条件建立；挖掘/走入/封口任何一步失败都不得写已避难。
- 清晨保有木镐/石镐等已完成进度，继续一次正常采集；结束无未结未知效果。

建议单次上限 35 分钟，总是记录失败原因。若 G4 已过而 S 组失败，应报告“基础机械链可用，生存闭环未过”，不能把两者混为一谈。

独立针对避难逻辑制造一次“place 返回 failed 但不抛异常”的故障：上层不得置 `sheltered=true`。该负例可用模拟返回值单测，真实过夜证据必须来自 LIVE。

## H. 防 checker 自证

Agent 必须实现并运行反例校验，至少证明下列篡改/缺失会使验收失败：
- 把失败动作的日志改为 sealed/success，但真实快照不变。
- 删除某个必需阶段的证据或仅保留最终截图。
- 混入不同 run、不同 jar、不同 world/session 的快照。
- 物品数量不守恒、产物只进 cursor 未入包、错物品落到目标格。
- 3×3 在没有合法工作台交互下出现产物。
- unknown 未对账却把上层标为 DONE。
- 五次测试中有失败、缺失或执行中换了候选，却报告 5/5。

这些是 checker 负例测试，不能伪装成真实 Minecraft LIVE。真实验收证据不得从 passing 示例复制。

## I. 自动化与回归

运行全套适用于本次构建的现有测试，以及新增行为测试。先列出基线，再逐项处理：本轮引入的失败必须关闭；不适用的旧源码字符串断言可被等价或更强的行为断言取代，必须解释，不能隐藏跳过。

不要求把历史 JUnit/GameTest 数量凑回某个固定值；要求测试发现正常、相关语义不丢、失败/跳过完整披露。旧 FakePlayer/Graph、crosshair、session fencing、Screen/Tom’s 和无透视边界保留适用回归。

固定 fixture 自动化、真实 Dedicated Server + Bob LIVE、最终 fresh build 三者分别报告，不能互相冒名替代。
