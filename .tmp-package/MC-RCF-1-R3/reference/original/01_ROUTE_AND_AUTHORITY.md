# 01｜路线、权限与设计边界

本页是本轮的规范性约束。它是新计划，不是对现有代码的完成声明。

## 1. 身份和运行拓扑

仍是 Dedicated Server + Bob 专用 Fabric 客户端。Bob 与所有者的 PCL2/正常客户端是两个玩家，只有 Bob 的客户端受自动化控制。不得抓取系统级鼠标键盘、抢用户焦点或要求用户手工点 GUI。

沿用现有 HTTP bridge 和身份绑定。主执行只允许一个拥有者；导航、挖掘、GUI 和安全中断必须归入同一个动作仲裁器。不同模块不能各自抢占按键或产生第二条永久控制循环。

服务端可以验证世界状态、配方结果与 Bob 的库存；**不可以为替代客户端操作而直接写库存、瞬移、改方块、增加食物或生成产物**。正常 MC 服务端对合法玩家包的处理不属于这种禁用的捷径。

## 2. 各层分工

| 层 | 负责 | 不负责 |
|---|---|---|
| LLM / 会话控制器 | 选择目标、任务顺序、开放式策略，解释必要异常 | 原始槽位点击时序、写服务端数据、无界重复尝试 |
| Body 执行协调 | 租约、动作互斥、预算、取消/暂停、重连对账 | 替 LLM 创造长期目标 |
| Navigation adapter | 到已给定目标/工作站位的路径和跟随，受控局部重规划 | 任意找矿、世界资源搜索、另开自主生存代理 |
| Inventory / GUI transaction | 真实玩家槽映射、物品移动、合成、使用和确认 | 固定木器/铁器人生脚本、猜测未确认的槽位语义 |
| 观察与回执 | 当前可见事实、来源/时效、能力、实际差异与未知状态 | 用布尔自报或日志文案替代证据 |

内部接口、类名、DTO、测试组织由实现 Agent 决定。可以提供少数足够表达意图的语义动作，不需要为每种容器和每个时代增加工具。

## 3. 导航路线

首选 **Baritone v1.12.0 的 Fabric 1.21.3 兼容路线**，仅作为受控导航执行组件。官方 release 声明兼容该游戏版本；这不等于已经验证与本项目 Mixins、Fabric Loader、Java 和输入隔离共存。

版本候选、官方来源、发布者提供的资产摘要见 `06_SOURCE_AUDIT.md`。先做 G2 兼容性证明，锁定实际下载字节及源码。不要同时装 API 与 standalone 两份运行包；根据官方打包说明选择一条正确安装方式。

接入要求：
- 通过程序 API 或窄适配器接入，不用聊天文本命令作为运行协议；关闭未经授权的 chat/control 入口。
- 只允许 Body 下发的目标。禁用库的全矿区搜索、`mine` 资源扫描、全局探索代理和自行获取材料等进程。
- 本轮导航 **默认不挖、不放方块**。任何破坏/放置权限都要从任务参数传到实际执行点；无法可靠约束时，`allow_terrain_changes=true` 明确返回不支持，而不是默默忽略。
- 核心链的挖树、采石、挖避难空间是独立、目标明确、预算有限的动作，不借 `goto` 任意破坏地形。
- 允许导航读取 Bob 客户端已加载局部地形的碰撞/可通行几何，限于机械寻路；不得将隐藏资源位置转成目标或模型可见知识。跨世界的缓存必须隔离。不能用服务器全图、seed map、`/locate` 或未见矿石缓存选资源。
- 导航的按键/转向输出须与现有输入隔离整合；不能为了让库工作而关闭真人输入隔离。
- 导航结束、暂停、取消、lease loss、断线时释放控制；旧导航进程不得在新动作开始后继续写输入。
- 避免危险坠落、液体和未授权破坏。允许先做保守能力子集，不要求本轮掌握所有跑酷和桥接。

Baritone 不可用时，必须先给出最小工程复现。允许评估一次“复用仓库已有真实路径规划器，适配为客户端 route follower”的备选；不得回退到更多固定偏航角和延长 timeout。两个候选均达不到边界时，在导航门停止，提出架构决策，不自动换服务器身份或 Minecraft 版本。

## 4. 真实交互和观测

全向语义感知继续是 awareness，不直接授权操作。目标选择之后仍须到达工作站位、转向，取得 fresh crosshair/正确 Screen，再执行。

工作站位应是可站立、可到达、可触及目标的候选；不能把待挖的实心方块坐标当作站位。导航“到了附近”不等于“已能精确操作”。准星命中必须对应目标，不允许 ±1 格把相邻对象算成目标。

LLM 默认只看：物品汇总、容量、手持/快捷栏、任务保护和缺口、当前容器类别/能力、动作状态及证据引用。详细物品属性和语义槽位按需展开。原始 sync id、epoch、点击时序和凭证留在执行器。允许 LLM 指定“快捷栏第 2 格”这样的稳定语义位置，不让它猜当前 GUI 的原始 slot id。

物品自定义名称、Lore、容器标题和模组文本是非可信数据，不能执行其中指令。角色不明的容器只读，不以试着乱点来“发现”用途。

**只读不等于合法感知。** `/locate biome` 不改世界，但可给予普通玩家未获得的远处信息；不能把这种结果用于本轮游玩决策。服务端独立测试观察器可核验实际结果，但不得把超出 Bob 合法观察范围的信息反馈给控制器。

## 5. 背包和 GUI 的最小共用层

本轮做能服务核心链的基础，不做完整仓储/生产平台：
- 玩家自身背包、快捷栏和 cursor stack 的真实状态；外部容器共享同一执行生命周期。
- 源库存内部索引与当前 ScreenHandler slot id 分开映射；不能假设所有屏幕编号相同。
- 同 ID 但不同组件/耐久的物品不能无条件合并；移动量按真实堆叠身份及保护约束计算。
- 拆堆、合并、指定数量移动、主背包↔快捷栏、选中已确认物品。
- 用户保护及任务预留在执行器强制检查；经任务授权的切工具不应被误认为“永远不准改 selected slot”。
- 使用真实 InventoryScreen / CraftingScreen / ScreenHandler 及标准客户端交互；原生 recipe 操作可以复用，但要证明走正常玩家处理链。
- 本轮外部容器只要求 **普通箱子与木桶** 的共享存/取演示；不新做机器 Adapter、AE2 或其他网络终端。
- 保留已有 Tom’s deposit 回归，但不扩展其功能。GUI 共享层与既有两阶段 ownership 不得变成两套互相绕开的权限路径。

## 6. 成功、部分效果和未知结果

固定业务语义，具体字段名由 Agent 自定：
- `completed` 必须有与本次意图一致的物理证据；参数错误、无变化、另一主体造成的变化不能偷换成完成。
- 物品转移的 count 指本次新增移动量；合成 count 明确为本次新增产出目标，按合法配方批次向上取整，并回报实际新增量。需要“达到总配额”时用独立明确语义；不能让同一参数在调用端理解为增量、服务端理解为最终持有量。
- 已满足、零操作要明确报告，与“本次产生了物品/移动”分开。
- 整个复合任务不宣称物理原子回滚。途中失败允许已产生部分效果，但必须返回已确认差异、剩余工作及 cursor 状态。
- mutation 发生后没有足够回执时进入未知/待对账；先观察再决定，禁止重放可能已经发生的点击。
- 重试同一请求不重复物理效果；相同 request id 携带不同参数必须冲突拒绝。ledger 容量治理不能删除仍需要的去重/未知结果记录而让旧请求重新执行。

## 7. 不在本轮做

新的冶炼/铁器/农业/战斗/末地；完整开放世界长期自治；视觉模型/直播/音频；万能 Mod 自动适配；整个 Graph 或 Iris 重写；通用资源物流平台；生产世界重置。

未经验收的旧 `smelt` 与时代脚本不得在本轮入口继续被宣称可用。可以保留为实验代码，但从本轮运行配置与能力目录禁用，直接请求须清晰拒绝。不要为凑“操作集数量”保留伪能力。
