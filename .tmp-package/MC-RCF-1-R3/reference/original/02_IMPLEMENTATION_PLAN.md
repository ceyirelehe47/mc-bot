# 02｜实施顺序与自主决策

每个门都执行“复现 → 改动 → 自动化 → 实机 → 回归 → 记录”。允许模块内并行开发；**同一个游戏实例、身体、租约只有一个执行者**。通过当前门后自动继续，不要每完成一个小步骤就停下来索要下一任务。

## G0：安全、可重建、当前事实

1. 刷新远端，记录审查 SHA、本地分支、工作区变更、后台时代脚本与本项目服务器/客户端进程。不得覆盖别人未提交的修改。
2. 用 `04_ENV_SECURITY_AND_REPLAY.md` 处理凭证、干净祖先和测试世界隔离。旧运行器只停止已确认属于该项目的 PID。
3. 盘点当前实际运行 jar 与对应源码，区分 `mc-bot` overlay、`mc-experiment/aibot` 活工作区、installer 和外部 Python 驱动。任何仅在活工作区存在的必要补丁都要纳入可重建源码。
4. 将本包源审查中的缺陷做短复现或调用路径核对，不直接照着旧结论机械改代码。记录当前实现集与宣称能力的差异。
5. 从空构建目录生成可运行客户端/服务端产物，锁定上游 commit、工具链、依赖、环境配置。文件夹名中的 `aibot-dsh-m0` 不代表还需启动 DSH。
6. 最小 smoke：启动 Dedicated Server、Bob JOIN、观察身份与背包、受控 say、正常退出/重连。验证客户端保持后台且不吞用户桌面输入。

产出：源码→构建→部署映射、环境指纹、已知失败清单、可复用的起停/清理命令。G0 不要求把历史几百条测试全部修好才看见 Bob，但要诚实保存基线失败。

## G1：先让执行状态可信

修复/实现：
- `play.py` 按错误类别处理提交失败；参数错、缺材料、能力不支持不能触发无关 cancel。抢占只接受明确授权和目标 execution identity。
- 保留单执行拥有者。客户端不能以“新命令来了”为由静默替换正在进行的动作。
- pause/cancel/terminal/session loss 清除该执行的按键、转向控制、破坏进程、GUI 事务与导航进程；清理要覆盖 useKey 等新增输入，不只旧挖掘按键。
- 服务端与客户端超时协调；高层可以更早取消，但要等待确定回执或进入 unknown，不能清掉变量就宣称空闲。
- 同一个 owner 的续租与重获不能变成固定 `llm-play` 越权；读查询不抢控制租约。
- 配额/增量、物品身份、目标绑定、幂等去重、部分效果、unknown 在所有本轮动作里保持一致。
- 客户端和服务端的 game-session/控制会话 fence 保留。若需要改变私有协议，显式版本化并拒绝不兼容旧端，不能静默混用。

用 `03_ACCEPTANCE.md` 的 C 组证明。先修生命周期，避免后续导航/GUI 的实机现象被旧执行污染。

## G2：成熟导航与工作站位

### G2a 兼容性小切片

在隔离客户端接入锁定 Baritone 候选，只测：启动无类加载/Mixin 冲突；后台可驱动；到一个安全目标；中途取消；取消后旧进程不再控制输入。不要此时启用挖矿/自动放置/全局探索。

检查输入隔离每 tick 清键是否覆盖库的期望输入；应由唯一仲裁器明确安排输入应用顺序，不关掉隔离。检查暂停 GUI 时导航不偷偷关屏、换槽或走动。

兼容性失败按 `05_EXECUTION_RULES.md` 的预算和备选流程处理；不得盲目升级到另一 Minecraft 小版本。

### G2b 正式窄适配

- 到位置与接近可交互目标分开；后者先求工作站位再到达/朝向验证。
- 站位评价包括脚/头空间、落脚支持、可达性、距离、危险和目标 LOS；候选来自已授权的局部几何。
- 到达判定按目标种类固定，不能用“离目标近了”统一替代；3D 高度不对不能算到达。
- 使用有限重规划/候选站位，保存已失败位置和原因；同条件不无限重复。
- 默认导航不挖不放。不支持的 terrain change 选项显式拒绝；支持时必须有范围/块数预算及检查，而不是允许任意挖穿。

通过 N 组地形用例。旧偏航/挖穿代码退出正式导航路径，不允许“双驱动各管一半”。

## G3：最小背包事务与四类动作

### G3a 通用物品移动基础

建立共享的观察、预检、计划、点击、同步等待、结果证明和安全收尾生命周期。不要先给 craft/eat/place 分别写绕过该层的临时方法。

玩家自身 screen 需要独立可验证的所有权规则；它不一定拥有外部容器那样的非零 sync id，不能照抄“handler 不等于 playerScreenHandler 才可用”的规则。外部 screen 必须关联真正打开的目标及当前 incarnation，不能只看类名。

最低覆盖：主背包中的指定物品调入快捷栏；指定数量拆分/合并；普通箱子与木桶存取；保护物不误用；cursor 不遗失；失败时已有部分效果可核对。执行前刷新物品与槽映射，不能用长期缓存原始 slot id。

### G3b 原生合成

撤下 Real Client 的 `InventoryCrafting.execute` 服务端写包路径。现有 recipe/planner 代码可以只作为经过验证的配方查询参考，不能以“材料守恒”替代客户端合成。

支持核心配方链：原木→对应木板；木板→木棍、工作台；工作台 3×3 → 木镐、石镐。至少橡木和另一种原木成功，不只硬编码 oak。

2×2 使用玩家本身合成界面；3×3 必须真实放置并打开工作台，屏幕绑定准确。工作台只在包里，或墙后/距离外存在工作台，不构成 3×3 使用权限。

优先利用当前版本的正常 recipe/ScreenHandler 交互。输入材料、配方有效性、合成余物、产物和 cursor 一起纳入证明；不宣称只支持本轮配方的实现已经是全配方/全模组合成系统。

### G3c 精确放置

接口表达“放置哪种物品/方块到哪一格”，不要只接受坐标后随便找一个 BlockItem。

由事务层准备实际物品与快捷栏，确定邻接支撑面和命中点，验证预计落点就是目标格，再发送正常交互。不能只看空气中心，点击任意准星命中面。

完成要证明目标块身份（必要时包含朝向/关键状态）、对应库存消耗和本次动作链一致。工作台不能被泥土替代；另一个玩家填了目标格不能算 Bob 完成。

### G3d 进食

在主背包定位实际选定食物，必要时真实调入快捷栏，验证手持后再使用；禁止“slot≥9 就传 0”。默认优先安全可食用物，不靠自动吃腐肉掩盖缺食物。

完成要证明本次食物消耗与正常使用效果，不接受仅因 selected slot 不在使用状态就自报吃完，也不能用其他事件导致的饥饿值变化冒充。

### G3e 精确采集

复用可修复的 `mine_opportunity`，保持 opportunity/位置/方块 incarnation 关联。不得按“最近同种方块”偷换目标。

工具不在快捷栏时走共享事务层；空手采集允许与否由游戏真实规则决定。物理破坏后确认目标变化、应有掉落和拾取。消失而未拾取是不同状态，不得仅凭一个累计库存数字就消解所有失败。

G3 通过 I/A 组后再进入核心链。`smelt` 此轮不实施，不为其预写铁器脚本；入口要明示不可用。

## G4：固定流程的完整基础闭环

用自动化测试驱动调用正式语义接口，不直接调用私有绕过路径。流程固定便于隔离执行器问题，不要求 LLM 边测试边自由发挥。

从声明且锁定的 fixture 初态开始：Bob 生存模式、空背包/空装备/空副手/空 cursor；附近有自然树形和安全可达石面，没有预先给的工具/工作台。

完整过程：观察/确认树目标 → 导航工作站位 → 采木并真实拾取 → 2×2 合成木板/木棍/工作台 → 指定放置工作台并打开 → 3×3 合成木镐 → 将镐调入快捷栏 → 精确采石并拾取至少 3 个圆石 → 3×3 合成石镐 → 核验最终状态。

最终保留木镐、石镐；工作台在记录的位置，能正常再打开；cursor 空，动作空闲。原木、材料和产物按本次运行账本可追踪。

五次运行矩阵提前确定，覆盖至少两种原木、两种地形布局和一次非默认快捷栏安排。每次都从对应干净初态重来，不继承上一轮合成物。

同一候选需要最终 5/5 连续通过。任何人工游戏内补救、半途换 jar、改代码或恢复存档都中止该次成功资格。不得以重复直到凑够五次成功隐藏失败率。

## G5：有界游玩、过夜与清洁复验

G4 通过后，才使用现有 LLM 会话通过正式语义接口完成“获取基础工具并安全度过一个完整夜晚”。不恢复 DSH；也不要求用户提供新付费模型才能验证。

两个预先声明的自然场景，保存不同 seed/初态。测试控制器可从 Bob 合法感知得知树、石和地形，不得输入 `/locate` 得来的资源坐标。使用已有 LLM 会话时完整记录其语义调用；不能偷偷用 woodage.py 全流程脚本冒充 LLM 泛化。

避难可以是利用合法可见的现成结构或明确的挖洞/封口动作，本轮不强制每次一个固定地形剧本。若选择封洞：确认每格挖掘、实际站位、入口封闭、墙顶支持、无已知立即危险后，才能进入 sheltered。动作失败不抛异常也必须阻止状态推进。

从黄昏之前开始准备，经历自然推进的整段夜晚到次日清晨。不能通过注销躲夜、时间指令、peaceful、kill 清怪、keepInventory、恢复存档或预给食物达成。此门不通过睡觉跳过夜晚。

两次均须 Bob 在线、无死亡、基础工具保存、无 unknown 未对账、无管理员/人工动作补救；次日能继续一个正常采集动作。不得只证明“停止发命令”而没证明安全。

最后从新构建目录、全新部署目录，用最终候选源码与锁定依赖重建：跑完整适用自动化、一个完整 G4 核心场景和关键取消/GUI 负例。通过后整理交付，不继续偷偷加功能。
