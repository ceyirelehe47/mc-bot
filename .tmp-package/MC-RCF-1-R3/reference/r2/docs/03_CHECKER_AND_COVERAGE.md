# 03｜验证必须验证真实实现

对应审查 R01、R04、R08。本轮不把测试失败解释成模型“态度问题”，要求能够重现和拒绝明确错误。

## 1. 同一个验收入口

最终报告、COVERAGE 和 READY_FOR_REVIEW 判定必须由实际最终 checker 产生。测试主 checker，不只测试它没有调用的 helper。不允许为反测试另写一个更严格的示例 checker，而生产交付继续使用旧 judge。

可以重构函数/API和证据格式，但转换器不能凭空补齐未采集的事实，不可用“旧格式一律拒绝”代替业务反例。区分格式检查、单用例结论、整套验收覆盖；不要把“格式合法且state=failed”当作成功业务用例的PASS。

`server_authoritative`、`completed`、`sheltered`、`PASS`、`cursor_empty=true` 均不是独立物理事实。状态和回执可作为输入之一，不能替代原始事件与前后快照。汇总字段与事实矛盾时判为不合格。

## 2. 四组历史反例必须保留

`reference/review_8626013/checker_counterexamples.json` 保存了四组不合格输入，旧 judge 全部误接受：

| 反例 | 不能放行的原因 |
|---|---|
| 单条A01＋server_authoritative文案 | 必测集合/物理事实均不全，不能通过I/A整门 |
| before=0、after=8、delta=32 | 数量矛盾；不管文案是什么都不成立 |
| 正向A01只有failed | 原生成功合成没有发生；不能拿负例状态规则放行 |
| 一次run复制五遍＋两把镐 | 重复运行身份、缺初态/过程，不能证明G4五次 |

包内 `tools/probe_checker_regressions.py` 可针对现有 `judge_ia/judge_g4` 离线运行原反例。它对旧判定器**预期返回非零**，这是检出已知缺陷，不是包损坏。修复或重构后须将等价反例接到真正的验收入口。该探针只有四类历史负例，**通过它不是整轮通过**。

## 3. 防止“全拒绝也绿”和“只改了helper”

每个语义反例要配一个来源明确的正例。通过同一入口分别判定正例和在隔离副本上做的单因素变异：

- 完整真实正例能够通过其对应的用例/套件；不能写一个永远False的拒绝器。
- 正例复制一份，篡改摘要但保留事实不变，结论不得被摘要带走。
- 正例缺任一必需阶段、混入另一运行/世界/产物、数量矛盾、错目标/组件、仅cursor产物、无合法工作台、unknown未对账，必须拒绝相应完成声明。
- 保留正确格式，并在需要时重算副本自身的文件摘要，使测试真正覆盖语义判定；不能所有负例只因格式错或checksum错就停在入口。
- G4 五个唯一run还要对应五组独立过程。复制同一证据改run名字和摘要也要被拒绝；检查实际事件、初态、时间线及重复材料来源，不只检查字符串不重复。
- 增加“正常取消/预期失败”的有效负例：场景要求拒绝时，验证前置触发与零额外效果才可PASS；不能把所有failed一律否定，也不能全部接受。

H6 必须把不一致数量送进主判定器，而非只调 `_delta_consistent`；保留直接helper单测可以，但不得用它顶替集成反例。记录被调用模块/入口版本、命令、返回码和判定理由。

## 4. V10 必须调用真实避难策略

stub 只模拟 place 返回值或环境；被测状态转换必须来自 G5 实际运行的策略模块。把“正确的if”重新写在测试函数里不能说明生产策略正确。

至少注入：place返回failed不抛异常；伪造completed文案但物理状态仍未封闭；前置挖洞/走入失败；已发生部分效果。真实策略均不得置sheltered。另有完整正例表明真正可核验避难条件成立时能进入安全状态。

策略尚不存在时就实现本轮G5所需最小策略或标NOT_RUN，不得把测试stub本身称为实现。

## 5. 覆盖不能由当前TESTS数组决定

完整保留原C01–C08、N01–N06每类三次、terrain三态、I01–I08、A01–A12、R1的L01–L10/V01–V10、G4五次、G5两次和fresh replay。`requirements/REQUIRED_ITEMS.txt` 是原要求的路由索引，不是新协议；每行可能含多个原子条件，执行一次不代表整行完成。

每条记录：真正前置条件、生产入口、模式、必要子场景、证据、判定理由及pass/fail/blocked/not_run。只完成子项则整条不能PASS。上轮“25/26”或“N18/18”不免检，也不能把L/V的子变体数量偷换成新的分母。
