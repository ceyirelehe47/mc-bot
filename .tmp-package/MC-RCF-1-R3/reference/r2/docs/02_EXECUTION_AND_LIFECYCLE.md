# 02｜确定性执行修复与生命周期剩余出口

对应审查 R03、R05、R06、R07。已有实现有价值，按真实路径修复，不回退成旧直线导航或服务器写包。

## 1. 进食：先修状态贯穿，再处理同步

已定位的控制流：phase=0，主包有食物、手持/快捷栏没有、cursor 空；PICKUP 源槽后设 cooldown，却既不 return 也不转阶段，随后跳过 phase=1，直接执行消费核验。此时 heldStart/consumedRounds 仍为默认零，返回 client_eat_no_effect。

必须先写一个调用真实 EatAction 状态转换/等效生产核心的确定性回归，复现该路径。不要仅给测试写一套独立正确状态机。修复后：

- 准备、取物、确认调槽、选择手持、开始使用、消费完成、收尾互斥；只有进入收尾状态才能判定消费。
- PICKUP 后至少等待相应槽位/cursor 的实际变化，不能靠固定 sleep 当同步确认；cooldown 仅节流。
- 实际食物来自主包时，共享事务负责安全调入；保留被保护工具，不默认占据0号槽，不在错误外部 Screen 上使用个人槽位编号。
- `isUsingItem: true → false` 也可能是取消/切物，不能单独定义成“吃完一件”。结合本次正常使用完成、物品身份与数量、服务器正常处理证据确认消费；不靠 remote reason 中 claimed 文案补归因。
- 消费一件后停止 use，不能固定按满一个窗口造成连吃。失败、暂停、断线均停止后续消费并记录已发生效果。

A08 覆盖主包、已有手持、空食物、满饥饿；C06 覆盖使用中取消；V04 覆盖外部移走物品或外部改变饥饿，不能误接受为本次成功。主包路径至少在同一候选上重复三次；这个重复是对已报不稳定问题的本轮明确补充，不替代其他必测项。

## 2. 所有退出路径收尾，不止显式 cancel

保留 finishAction 的方向，但把生产调用图核对完整：普通 complete、普通 fail、格式错误且归属当前执行、异常、硬/软超时、pause、lease/control loss、死亡/世界/维度/session 变化、授权替换以及无 player 的分支。

每个路径均要求：停止新业务调度、终止 Baritone 路径/目标与转向、释放全部业务输入/破坏、处理或登记 cursor/GUI 恢复义务、发送与事实一致的回执。清理应幂等；不能在通用 clearInputs 每个 tick 都取消正常导航。成功终态不能先对外释放执行槽，实际动作却仍在运行。

暂停保留意图但不保留继续写键的导航。恢复时重新验证身份、Screen 和目标；若暂停关闭了 GUI，不能恢复旧的 raw slot 计划。取消后最多10 client ticks 不再生成新业务动作；在途正常包/惯性以及事先允许的有界物品收尾单独记账，不承诺回滚。

有 cursor 时不能一律关屏当“安全”，更不能跨新屏回填。无法确认合法归还位置则停止并报告恢复债务/unknown。需要时将有效权限下的有界回包收尾纳入状态机；已失去身份后不得为了清光标继续写新界面。

## 3. 生命周期：保留 intent，补齐实例全量事实

继续用唯一入口，先假进程测试，后有限实机确认：

- **stop 无记录**：仍扫描本轮命名空间与待决意图；有孤儿不能返回全 STOPPED。归属可证明则安全处理/接管，不能证明就 BLOCKED，不能误杀无关实例。
- **已有一个合法记录**：start/status/stop 仍核对本轮同角色额外实例及冲突；不能在 `_verified` 成功后提前认为配额合规。
- **失败预算**：记录哪个角色/哪条恢复链有未结失败。server 连败后 client 成功、反向情形、stop、换 run_id、重开脚本都不能清除它。只在对应故障真实修复并验证后按授权恢复；三败锁不得自动 unlock。
- **STOPPING/STOP_FAILED 与排队请求**：旧队列中的 start 不得推翻后来明确的 stop。记录期望状态和操作先后；新明确 start 与旧看门狗恢复区分。
- **枚举健康**：权限/命令行不可读、解析异常、进程查询出错不是空集。fake 模式与真实凭证、状态、锁和 marker 隔离；伪进程测试不得在真实根目录重置状态。
- **原子身份**：停止前再核验 PID/创建时间/marker 或等效稳定句柄，不能靠陈旧 PID；游戏子树残留有明确结果。
- **就绪**：Bob 在线或出现某个日志词不等于当前 PID 已就绪。对应到本次实例和服务端/游戏会话。

沿用 L01–L10，不要求为凑测试数反复杀真实游戏。普通 PCL2、生产世界、无关 Java 和 Gradle 不得受影响。外层 harness 没有真正限制任意 Shell 时如实披露；任务书和文件锁不是操作系统沙箱。

## 4. 合成、放置、移动的实际证明

### 合成

`count=q` 是本次新增请求，若每合法批次产出 p，则完整执行 `ceil(q/p)` 批应产生相应的完整批次产出。例：q=5、p=4，完整两批应产8，不能delta=5仍叫两批完成；q=32只有8也必须拒绝 completed。

在计划/动作开始捕获必要材料基线，逐阶段记录实际正常槽位结果，确认材料消耗、产物真正入包、余料、合成格、cursor 和受保护对象。不能只把 `min(want,fullOutput)` 换一个字符串；不能只测文案中的数字。部分产出准确报告，不能伪称零副作用或完整完成。正常效果受并发影响而不能归因则 unknown/冲突，不虚构守恒。

3×3 必须绑定那张真实已打开工作台及屏幕 incarnation，不只验证同类型类名与 syncId。2×2 同样受个人 Screen/handler 身份保护。原生点击保留，服务端只负责验证，不直接变换背包。

### 放置

目标类型正确＋库存减少仍可能同时来自两件无关事件。用本次客户端交互、服务器正常处理或等效可核验事件将 Bob、目标格、物品与本次执行关联。测试他人放同类型块并另因减少 Bob 物品、无有效交互、相邻格变化。

目标已存在但消费/归因未证时可有界等待；timeout、取消、失败检查必须覆盖这条 waiting 分支，不能提前 return running 绕过预算。完成后立即终止旧重试，不在下一执行期间继续点击。

### 移动与容器

保留增量语义：目标原有10，本次移7，净增必须7，源净减7；整堆绑定具体源对象和当时数量，不能目的槽本来有同类就 no-op 冒充移动。至少同时核验组件、源/目标/保护槽以及cursor，不以总量不变替代身份。

普通箱子和木桶各自存入、取出都要实际执行。只完成“箱子存取＋木桶存”不够。个人包、工作台、容器的槽位映射由当前 handler 归属决定，不猜通用基址。未知/ghost/只取不放槽位必须 fail-closed。

Tom’s 只做已有 deposit 回归，不扩展它；要搭真实终端，正常开屏、转移、双侧验证和保留工具。没有装置只能报告 NOT_RUN/BLOCKED，不能把一个空目标 deposit 的失败当成功回归。

## 5. 不新增旁路

smelt、旧时代无人值守编排和旧启动器维持实际禁用；通过所有对外入口直接请求也要拒绝。不得为通过本轮悄悄放开服务端合成、FakePlayer、系统输入模拟、无透视例外或资源替代。
