# 04｜先收敛故障，再做核心链，不再无限放跑

原完整验收矩阵在 `reference/original/03_ACCEPTANCE.md`；R1的L/V细目在 `reference/r1/docs/02_ACCEPTANCE_AND_RUNS.md`。本页明确本轮实施顺序，不减少最终条件。

## 阶段0：保全与可追溯起点

刷新远端；保存不明改动和已有原始日志；确认没有游玩脚本/看门狗持续竞争。建立准确覆盖账：未验证的PASS恢复为未通过状态，上轮证据不删除、不重写。先记录源树、依赖、隔离world、当前进程和实际jar身份。

复用现有隔离环境；新目录不代表允许再开一套游戏。一个权威源码树生成build树，不在三个副本手工同步Java。

## 阶段1：安全与确定性缺陷

L剩余故障先用隔离假进程；checker历史反例、EatAction状态贯穿、所有退出路径、机会校验顺序与journal一致性先做确定性回归。可并行编码/离线验证，LIVE仍只有协调者。

本阶段至少关闭：重复实例风险、正常/异常收尾、读接口不能出生机会、合法转向后能出生、主包进食不贯穿、数量/归因关键反例。通过后有限实机确认。未通过不跑完整计分或夜间放跑。

## 阶段2：一条非计分诊断核心链

**本轮新增的推进顺序安排：不必等几十份报告都排完版，先用已修基础获得一次真实串联结果。** 这是开发模式，不能标B01 PASS，也不能替代最终五次。

用一个预先声明、可重复的小型fixture：正常可站地面、可见且可触及的自然树形/暴露树干、可见石面，在现有导航和动作支持范围内。构造fixture是测试准备，不是声称这是自然野外成绩。不要将绕复杂山脊、碰巧掉落的树叶、额外清障当成验证“采木—木镐—采石—石镐”的必要新变量。

run开始前允许固定测试世界/地形和空包；开始后只能从合法感知选目标、正常转向和操作。不得中途给物、传送、删遮挡、铺垫脚块、改时间/难度来救场。真实需要清障时必须由已授权的正常动作完成，并区分“清掉无掉落障碍”和“取得资源”。没有此能力时先使用已声明的可见资源fixture，不做伪资源增量。

保留一个runner、一个owner/session及有限恢复上下文。资源选择、准星取得、submit、执行、对账每阶段只有一个明确入口，不用新建Session来查背包/机会从而抢掉自己租约。只读操作不能推进业务。

盘点 `tools/rcf1_g4.py` 遗留骨架：删除或禁用重复分发的条件表达式，核对观察响应的实际容器类型，不能同时假设inventory是映射又按对象列表遍历。每次语义动作只发一次，失败路径有前后事实。未调用的旧半成品不要作为正式备用入口。

链路是：

```text
空包观察 → 选择可见原木 → 合法转向/机会 → 正常挖掘并拾取
→ 原生2×2木板/木棍/工作台 → 精确放置并打开工作台
→ 原生3×3木镐 → 调入/选择正确工具 → 实际采石拾取圆石
→ 原生3×3石镐 → 木镐与石镐同时在包
→ 重新打开原工作台成功 → cursor空/导航和输入结束
```

一次失败就保存精确停点再做最小复现。不能只输出“stale”后扩大扫射角度。诊断单次仍限制12分钟；同条件连续两次无进展必须停下。

## 阶段3：固定最终候选，完成真实矩阵

诊断串联成功且相关实现稳定后提交生产候选C：生产代码、installer、资源、依赖和行为配置全部固定。编译和测试脚本版本另记。用C构建并实际部署，先重跑适用自动化、完整C/N/I/A与L/V（可复用能证明来自同一C/对应工具版本且无污染的本轮原始记录，不复制旧摘要）。

每个未测子场景仍是缺口。N六类各三次，普通成功≤120秒；不可达按预声明预算。C02/C06覆盖导航、采集、GUI，而非只有goto。C08不能拿批量加开游戏冒充真人共存：只使用已安全存在的普通客户端或经既有授权的合规测试观察条件；不得冒用用户凭证、强制用户点击。不具备条件时如实列环境阻塞，不谎称全部通过。

## 阶段4：G4五次完整连续

固定五个唯一run，预先写定：两个橡木、两个第二树种、一个非默认快捷栏/堆叠布局。布局扰动在空包开局后用真实事务产生。每次≤12分钟；材料必须本次采集，不预给原木/圆石/工具。

每次须具备：初始空包、采木、原生2×2、精确工作台、原生木镐、木镐真实采石及拾取、原生石镐、两把镐当前同时存在、重开原工作台、cursor和控制收尾、无未决unknown。材料链和原生交互证据完整。

有一次失败就保留失败；修代码/行为配置产生新C后重新开始完整五次，不能挑选五次零散成功。纯checker收紧可对足够的旧原始事实重算，缺事实则实跑；不得放宽断言让失败翻绿。不能复制一次run修改ID再算五次。

## 阶段5：G5两次自然过夜与fresh replay

G4通过后才启动有界LLM游玩。原S组要求不变：两次自然场景从空包、正常资源、正常工具发展、黄昏前实际避难，在线经过自然完整夜晚到清晨，无睡觉跳夜/登出避夜/死亡重生/keepInventory/改时间天气难度/管理员补给。清晨保有进度并继续一次正常采集。建议每次上限35分钟，实施期间不改生产代码。

避难判定必须用真实策略与可核验世界条件。V10的stub只提供环境结果，不能替代真实策略。生存失败单列，不能抹去G4成果，也不能声称整轮成功。

fresh replay从新目录取得C和锁定上游，生成源码、构建、适用自动化，原受管实例退出后再部署新run目录，重跑完整核心链一次和关键取消/GUI/无台/机会边界负例。不得复用活树class或临时patch。

## 6. 时间与停止纪律

本轮最多12小时主动实施/验证；同一关键失败三轮有效修复上限。定义失败签名包含目标阶段、违背的不变量、错误与前置条件，不能把“同一准星交接一直不成立”改叫新的子问题来无限续跑。新测出不同缺陷可登记，但整体窗口不重置。

阶段门没有通过不能打PASS。阶段性push不自动结束任务；安全阻塞/预算上限/明确停止指令则保存现场、停止本轮实例。可以完成安全且独立的离线项，但不能运行受阻的下游计分。

达到窗口仍无完整核心链：提交最后稳定子链、失败帧/事件、最小复现、已尝试假设和明确下一动作，不再写更大的时代脚本，也不自行降级真实客户端路线。
