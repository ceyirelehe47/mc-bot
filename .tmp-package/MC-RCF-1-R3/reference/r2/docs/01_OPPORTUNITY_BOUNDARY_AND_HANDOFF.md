# 01｜机会出生边界与可用的目标准备链

对应独立审查 R02，并直接处理 G4 的 observe → dispatch → mine 阻塞。**不能只删 sweep 后留下完全无法产生新机会的执行系统。必须把合法的准星链修到能持续工作。**

## 1. 不变的权威

```text
只读全向感知发现可见候选
→ 从合法观察中选定具体目标
→ 正常导航到可站、可触及、视线成立的位置
→ 正常转向，等待该姿态之后的新客户端帧
→ 服务端验证帧身份/新鲜度/位置/精确准星
→ 对该方块 incarnation 出生或刷新机会
→ 正常客户端挖掘/交互
→ 破坏、拾取与持久结果分别核验
```

“看见候选”“知道目标”“已获得执行资格”“已破坏”“已拾取”不是同一个状态。实现内部形式自由，但不得合并成一个布尔值。

### 必须撤下的旁路

- 全向扫描不得直接 `register → appendBirth`，也不能换方法名保留相同行为。
- `inspect_local` 等读接口不得靠调用 tracker 的写入过程补机会，更不能读一次就顺带修 journal。传感器正常后台处理与读接口分离。
- `client_crosshair_server_validated` 只能用于真正经过当前客户端准星和服务器一致性校验的证据。全向观察仍用原语义来源，不得靠改标签“合规”。
- 不能因为一段 raycast 不穿墙就认定其具备机会出生权。LOS 是必要条件之一，不替代准星、身份、帧和具体目标。

旧代码 observe 中 freshness-only 的 sweep 放在 crosshairPresent、game-session、frame 去重、位置一致性之前。修复需确保**所有拒绝条件生效前没有 durable birth/可执行机会副作用**；不要求推翻传输层已经验证过的东西，但要证明完整调用链实际覆盖这些条件。

## 2. 可重复的准星交接，而不是“等一等”

定位并记录一次最小目标从选择到 submit 的时间线：目标/世界/维度、身体与眼部位置、选择时证据、导航站位、转向完成、客户端帧、服务器校验、机会 incarnation、提交与首次真实物理动作。帧序号只在其会话内解释，不能比较不同会话的裸数字。

用于生成机会的帧必须比本次必要的转向/重新站位更新，目标格及需要的面匹配，并属于当前 game/control 身份。旧帧、重复/乱序帧、缺准星、位置漂移、跨维度、帧内容与服务器 ray 不一致，都不能借 fallback 扫描通过。

不得把资源实心格当站位。站位与交互点分开，验证脚/头空间、支撑、危险边界、实际路径、合法触及和 LOS。允许利用当前导航适配器，不新增完整路径规划器。定位误差可以采用有依据的容差，但不能放宽目标格、准星或 Screen 身份来迁就误差。

准星确认与动作准入之间可能发生真实变化。必须区分：

- **尚无 mutation，只是帧过期/姿态改变**：可以有界重新站位、转向并取得新帧；仍绑定原目标及当前 incarnation，记录新的准入依据。
- **目标被移除/替换，包括同类型重新放回**：旧计划失效，不自动换最近同种方块，不重用旧出生记录。上层基于新观察另起计划才可选择新对象。
- **Bob 已破坏、拾取尚未完成**：进入本次采集的拾取义务，不再尝试对空气重挖；已有掉落、拾取不可达/被别人拿走/死亡分别核算。
- **断线或确认丢失**：先对账，不把新的 Session 或 request ID 当成允许重做的证据。

恢复预算按同一意图持续保存，不能每次刷新都重置。返回 typed 失败和已发生效果；不以多次 inspect、扩容或永久重试替代闭环。

## 3. 机会池与持久账本

当前惰性 `removeIf` 不写 stale receipt、replay 超容量跳过 birth，均需要检查并修正：

- 删除/消费/失效要有可追溯的持久语义，崩溃前后结果一致；只读列表不顺带写新出生/静默丢状态。
- 内存缓存上限与持久事实区分。可以有界缓存、快照/压缩或明确失效流程，但不能忽略中间 birth 后再假装完整重放，也不能为一时容量问题无限扩 MAX_ACTIVE。
- 对已处理记录的复用、同位置同类型的新 incarnation、旧世界/维度污染、达到容量后重启分别验证。
- 查询输出保留原有 radius、数量、截断和 freshness 边界。新机会列表不能绕开 local 查询范围，把整维度缓存不加界限塞给 LLM。
- 遥远/不可见的真实世界状态不能经“清缓存”过程变成模型的额外隐藏世界信息。

本轮不要求一个全新通用 journal 框架。以最小可重建修复证明正确性，保留原 Graph/FakePlayer 适用回归。

## 4. 准入前必须实际运行的针对性验证

复用 A09/A10/A12、C03/C04/C07 和原 awareness 测试，不用为凑数量新建独立测试宇宙：

**读与出生分离**：只有侧后方可见候选、准星未指向它时，反复 local/view 查询不得让该候选产生 birth、Graph node 或 mutation。后台恰好验证了其他准星目标的出生须按帧和目标分清，不能用“journal 总量变化”草率归因。纯函数/隔离入口测试补充 LIVE 时间线。

**合法转向正例**：同一候选正常转向后，取得新鲜精确帧，出生一次并能 submit。后续同一合法观察可刷新 last-seen，不重复 birth。

**拒绝无副作用**：对身份、帧、位置、ray、目标各项错误，用真实被测入口或可注入的确定性测试证明不写 durable birth；不能只测一个从未被生产调用的校验 helper。

**连续采集**：取第一根原木、走到掉落并拾取、再观察第二个目标，合法生成新机会并继续；每次刷新不偷换目标。另测目标移除、同类型重建、外部拾取以及重启后的未决状态。

对不能归因的现象先保存具体帧/目标/阶段，禁止笼统写“注册不稳所以再扫360°”。
