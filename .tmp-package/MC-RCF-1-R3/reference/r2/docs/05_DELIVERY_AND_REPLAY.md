# 05｜交付事实、来源绑定与独立审查

## 1. 本轮交付目录

建议 `deliveries/mc-rcf1-r2/` 包含：RESULT、COVERAGE、FIXES、BASELINE、REPRODUCE，以及tests/live/audit。结构可调整，审查入口与文件关系必须清楚。

- **RESULT**：开头给真实整体状态；分别列修复、完整回归、G4、G5、fresh replay、外部安全条件。使用 `templates/RESULT.zh-CN.md` 可避免漏项。
- **COVERAGE**：从原矩阵/R1补充生成完整分母；子条件不足不能整行PASS；状态与真实checker结果一致。
- **FIXES**：审查R01–R08逐项关联真实复现、代码变更、测试入口、失败和最终重测；本轮新定位G4 runner问题另列，不伪称旧审查已复现。
- **BASELINE**：完整源码C、锁定上游、依赖配置、构建输入/输出与两端实际加载身份；不写“见git log”“本分支HEAD”。
- **REPRODUCE**：从新目录可执行的准确命令，含主checker、反例、构建、生命周期、fixture、计分和清理。不能依赖没有交付的历史目录client命令模板。
- **tests/live**：真实原始脱敏快照/事件、请求与回执、前置条件、派生结果、失败尝试。不能只交一张汇总或只交C/N两个JSON。
- **audit**：完整性/安全/来源、覆盖重算、独立审查或明确非独立二次自审。

## 2. 证据最低内容，不锁字段名

每条结论都能串回：完整40位源码SHA、实际产物SHA-256、依赖/行为配置指纹、测试/采集器/checker版本、world/run/session/执行身份、时钟/ticks、前后状态、正常客户端动作与服务器处理、拒绝/失败原因及部分效果。

消费、放置和合成须有正常处理链的归因事实，不用新加一段“server_authoritative”文字来替代。原始事件缺失就说明缺失；不得把reason解析再重新包装成所谓原始server事实。

对取消/断线/重连测试允许一条run包含明确记录的多session转换；不能机械要求全程同一session让恢复测试无法成立。跨world/候选/产物混入仍须拒绝。

G4/G5从空包计分的正式开始标记之前完成fixture核验；之后管理员只读oracle与预声明负例注入单独隔离、留审计轨迹，不给LLM/Body看隐藏信息。真实失败和完整尝试序列都保留。

## 3. 源码、构建、运行不能靠文件名相同

一个权威源码生成树；任何修复先进入该权威，不在活树/重放树手工cp。构建记录输入、命令、退出码、测试发现/失败/跳过和完整产物清单。remapJar成功不等于build/test成功。

旧45项GameTest失败不是可永久忽略清单。先核对实际基线，触及机会出生、持久账本、收尾、Screen等语义的旧失败必须修复或用等价/更强行为覆盖替代；新增失败必须关闭。未触及既有失败准确披露，不凑固定历史数量，也不静默删除测试。

候选C包含所有影响行为的源/资源/依赖/配置；证据提交E允许在其后追加测试报告。若E又改生产行为就变成新候选并按规则重测。C/E关系、实际加载字节与进程会话有明确收据；仅修改README不改变游戏行为，修改fixture或checker要登记其版本及影响。

为避免自指提交循环，最终远端HEAD写最终回复或仓库外最终收据，不为了把自身SHA写回自身文件不断追加commit。JAR非确定性时间戳允许说明，类/资源差异不能宽泛豁免。

## 4. 安全、推送与停机

未净化wire、凭证/租约state、完整环境、第三方JAR和崩溃dump留仓库外。上传事实必须足够重算但已经真正脱敏；完整哈希不等于可以公开秘密值。每次推送前扫描index、待推提交和相关可达历史，不绕push protection。

用户外部账户撤销/轮换与共享历史清理未被本任务自动授权；不能验证泄露密钥是否有效，不能自行force push或删远端历史。可用安全本地新凭证继续隔离实施，外部条件单列。旧孤儿分支名称不是无秘密证明。

结束前通过唯一入口停止本轮实例并核验真实状态；status/stop遇到不明孤儿不得伪报全停。保留用户正常客户端与生产世界，不在交付后继续跑计分。

## 5. 独立审查不靠同一份自报

有subagent时让只读审查角色复核生产入口、故障fixture、主checker和真实事实；不启动游戏，不抢租约。没有独立角色则明确二次自审，不能虚构独立审查。

至少重算：合法准星出生正/反例、主包进食、终态停止、孤儿stop/跨角色预算、cursor三阶段、Tom’s真实转移、一次完整核心链与五次唯一性。必须实际调用最终checker主入口，检验四个历史反例及完整正例的语义变异，不只接受工具最后一行。

**READY_FOR_REVIEW只表示本轮所要求的实现、证据与重放满足；不证明已经通关、适配任意Mod或长期无人值守。** 未完成G4/G5或存在本轮核心缺陷就PARTIAL/BLOCKED，不把“补充修复门通过”换名成整个目标达成。
