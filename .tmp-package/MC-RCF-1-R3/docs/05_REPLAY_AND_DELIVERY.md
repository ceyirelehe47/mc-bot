# 05｜重建与交付：从证据能回到实际运行

## 1. 真正的fresh replay

全新空的生成/构建目录，来源只能是锁定上游revision、固定C中的overlay/installer/受跟踪资源、明确锁定的依赖。可以复用经校验的下载缓存或构建依赖缓存；不能复制旧构建树源码、未提交本地修复、旧classes或以robocopy排除build/.gradle冒充生成。

installer缺文件、启动模板依赖某旧实验目录，先修进仓库并纳入候选；严禁在replay树手工补丁后照样报zero diff。对比生成源码/资源/构建输入内容，记录实际命令、退出码、发现测试/失败/跳过及完整产物列表。

新server/client部署目录从可再生配置模板与经授权的秘密注入建立，不能复用旧mods/current world配置隐藏依赖。先通过唯一管理器确认旧实例全停，再使用新目录启动同一配额的一对进程。准备期可复制预先声明且哈希固定的测试世界快照；明示来源，不带入正在运行的旧世界/未决日志冒充空白重放。

固定完整C与运行脚本版本。两端实际加载产物由启动/运行握手或等效可追溯信息核验，不能只hash一个“准备部署”的磁盘文件。模块JAR哈希不同不得仅称“时间戳”：给出解包内容逐项比较，说明可忽略的归档元信息及真实行为资源完全一致；如果类/资源不同则新候选或阻塞。无需强求可重复压缩字节，但不能用前缀哈希代替完整值。

运行适用自动化、重放核心链和关键反例（外部移物不是进食、无台3×3拒绝、超距/错误支撑放置拒绝、取消清理及无权限推进）。证明输入版本、加载新产物和这次执行有关联。跨会话重连负例保留真实转换，不伪造相同session。

## 2. 交付入口保持少而可追踪

本轮 `deliveries/mc-rcf1-r3/` 至少包含 RESULT、COVERAGE、BASELINE、FIXES、REPRODUCE、证据索引及 tests/live/audit 的必要原始脱敏事实。目录内部具体组织由实现者选，以下内容不能少：

- **RESULT**：真实总体状态、各门与遗留；候选/runner/collector/checker身份；不能“其余PASS”掩盖I08/C08缺项。
- **COVERAGE**：按原子条件分母、成功/失败/未跑/阻塞、真实入口与证据位置；可机器生成，不从测试函数数组生成分母。
- **BASELINE**：完整C、上游、依赖、有效配置、两端实际加载完整SHA256、原构建与重放映射。禁止“见git log”“本分支HEAD”或省略号。
- **FIXES**：F01–F07与继承未结条件的复现、修复、真实测试和结论；不要把排查假设写成已证根因。
- **REPRODUCE**：从空目录开始可执行命令与必要安全前置，含生成、构建、启动、fixture、checker、语义变异和停机。不依赖未交付的历史绝对路径模板。
- **原始事实**：完整未截断的必要请求/回执/状态与正常游戏事件；不是所有日志倾倒。敏感值净化，身份可用一致非秘密映射，不改变时序/数值/目标/组件的验收语义。
- **失败账**：所有正式尝试与修改边界，G5失败也实际落盘；不得只在函数成功末尾save导致失败链消失。latest别名指向真实本轮记录，manifest索引验证内容与候选，不复制旧JSON换名。
- **审查记录**：验证者实际调用主入口的结果、正反例、证据缺项、最终停机与残留实例检查。没有独立角色时明示二次自审。

提交生产候选、测试/runner版本、证据提交的关系清楚。最终远端HEAD写在最终回复或仓库外收据，不为把自身SHA写入同个文件无限追加commit。候选后若改G5生产策略等行为，就建立新候选并按影响重测，不能把它标成“仅文档”。

## 3. 密钥与安全

不提交token、含凭证的状态、原始环境转储、第三方JAR、未净化wire和dump。扫描暂存区、待推提交与相关新增历史，不绕过push protection。旧外部凭证轮换/共享历史处理未由本任务授权，不测试有效性、不偷偷force push。安全隔离实施所需新本地凭证按既有权限生成与注入，归档只记非秘密身份/配置摘要。

## 4. 完成报告模板

使用 `templates/RESULT.zh-CN.md`。每个“通过”能从索引追到实际文件，并能由最终checker重算。完整性自检成功不等于Minecraft通过，离线纯核心通过不等于LIVE通过，复制树重编译不等于fresh replay。
