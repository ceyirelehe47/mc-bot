# 02｜事实采集与最终判定：不再围绕布尔值加壳

对应 F01/F02/F07。原始事实、运行摘要、单用例结论、完整覆盖必须分层。以下约束的是证据含义，不固定 JSON 字段。

## 1. 谁决定结果

采集器记录实际发生的请求、正常客户端交互/服务器处理、观测、完整终态和进程/产物身份。采集失败要写缺口，禁止 `.get(..., {})` 把错误响应当“空背包初态”；没有 cursor 观测就是未知，不是空；没有 ledger 对账就是未知，不是已清。

摘要由主 checker 从事实产生。`PASS`、`server_authoritative`、`chain.*=true`、`precondition_established`、`zero_extra_effect` 只能是派生/展示结果，不能成为物理证明。reason 算术可作交叉检查，但把 reason 解析后再次包装不等于多了一个独立来源。输入摘要与事件矛盾必须明确拒绝完成声明，不能默默只挑对自己有利的一份。

唯一最终入口同时覆盖：格式/完整性、单用例的预期行为、整套必需条件、G4、G5、replay、整体结论。可以重构现有 judge-ia/judge-g4 并增加入口，但最终 RESULT/COVERAGE 必须来自这个实现。没有 I08 的整套 I/A 不能接受；可给其他单项有效 PASS，不以整套拒绝抹掉真实成果。

## 2. 最少但足够的事实链

- **运行身份**：源码 C、实际客户端/服务端加载产物完整哈希、行为配置/依赖、runner/collector/checker 版本；真实 world、Bob UUID、game/control 会话、run 起止、执行与机会/Screen 身份。
- **初态和前置**：成功读取的空主包/装备/副手/cursor、控制取得、场景准备结束；物资/方块/容器/故障触发的原始状态，不靠注释。
- **动作归因**：完整请求、精确目标/物品、实际正常交互事件及服务器效果；部分执行与失败保留。对 fungible 物资，在隔离场景中按数量守恒与合法采集/拾取事件对账即可，不要求给每个圆石造不可实现的永久身份。
- **后态**：实际库存/组件、cursor 与合成格、目标方块/原工作台重新打开、路径/输入收尾、未决 ledger。每项对应哪次原始观测必须可定位。
- **时间与尝试**：wall time 及必要的 client/server ticks；所有尝试按真实顺序保留，正式五次预先登记，修改行为后不能拼接以前成功。

允许同一个真实游戏／控制会话连续跑五次 G4：身份必须真实，run 的初态、事件范围和尝试序号独立且不重叠；**不要求为了凑五个 session 字符串而重启或重连五次**。session 不能由 run 名+时间冒充。恢复负例可以跨会话，但转换和未决效果必须可对账；无故混入其他 run/world/候选事实拒绝。

上游请求失败、空返回、部分读取、类型错误不允许静默变默认成功。重复 case ID 不许字典覆盖抹掉 failed/unknown；重复用例尝试使用明确子场景/attempt 身份并完整计数。可在一次场景中含有效正反例，但不得让最后一次状态遮住未结效果。

## 3. 新反例与正常正例一起通过同一入口

参考 `reference/review_ff29078/synthetic_inputs/`：七组误接受与三组拒绝对照。包内新探针直接调用目标 CLI；严格区分明确拒绝与崩溃/超时/用法错误。历史反例可以因旧格式被拒绝，但这**只证明兼容拒绝**。

每个缺陷必须另外从本轮完整有效证据生成格式正确的单因素变异，必要时重算文件哈希，让输入真正走到业务判定。至少覆盖：

| 变异类别 | 必须拒绝的错误声明 |
|---|---|
| 只有 ID/文案/布尔，或阶段被删除 | 未提供原始事实仍宣称完成 |
| 回执算术正确但请求/快照不符 | 没有新增/少产、源未减、错物品/组件 |
| 重复 ID 遮住 unknown；缺候选/加载身份 | 不完整或跨运行污染仍宣称整门通过 |
| 改 run 名、session 标签、nonce 后复制同一事件 | 五个名字冒充五次独立尝试 |
| 事件失败/cursor 非空而摘要全真 | 摘要覆盖反证 |
| 初始工具非空或中途给物/传送 | 非法取得进度仍算空包成功 |
| G5 查询错误/身体不在洞中/空包到清晨 | unknown 被当安全，或进度丢失仍过 |
| 死亡重生、登出跳夜、oracle 私有事实进策略 | 非自然连续在线过夜仍算成功 |
| 四次成功/混入旧候选/插入失败再挑五条 | 未完成同候选连续矩阵 |

还要有真实成功正例、真实预期拒绝正例、允许且完成对账的部分效果/恢复案例。不能把所有 failed 都过，也不能全部拒绝。哪些子场景允许部分效果按原矩阵判定，不能一律要求零效果把正确的失败恢复也判错。

`tools/probe_checker_cli.py --pairs ...` 支持成对输入。manifest 只是探针配置，不是生产 schema；每对正例须通过、对应语义变异须明确拒绝。Agent 制作真实采集正例与变异，不能用包内合成数据冒充 LIVE。至少一组 G4 正例与所有相关反例通过同一最终入口，再进入正式计分。

## 4. 覆盖与旧证据复用

原 C01–C08、N01–N06 每类三次、N-TERRAIN、I01–I08、A01–A12、L/V 原条件、B01–B05、S01–S02、FRESH-REPLAY 保留。R2 的 L11–L13 是生命周期补充变体，也必须保留。具体分母来自文档原子条件，而不是当前 tests 数组长度。

旧记录有完整同候选/同配置事实、来源可信且语义未受本轮修改影响时，允许重算复用，逐项写出理由。旧摘要只有 true、截断回执、缺加载身份的部分只能是历史诊断，不许事后补成原始事实。生产行为变更后的正式 G4/G5 仍须在最终候选执行；不跨候选拼五次。纯 checker 修正可重算同一份完整事实，不为改报告文字机械重开游戏。

等价覆盖须逐子条件映射入口、触发、原始证据和断言。C07 的批量阈值/重启去重不能只引用类名；C06 的 use/attack/cursor 三类不能只用 I06 的一个取消；C08 无授权共存环境保持 NOT_RUN，不偷偷启动用户客户端，也不冒领整轮 READY。缺项不妨碍继续其它安全可完成部分。

## 5. 验证范围的现实边界

本轮是在测试固定版本工具是否诚实可靠，不建设能对抗拥有任意 Shell 权限的恶意开发者的密码学证明系统。来源锁定、独立观察、隔离权限、原始事实与语义变异足以用于这一轮工程验收；“文件 hash 完整”也不自动证明内容真实。无法验证的地方明确保留未知，不堆字段制造确定性。
