# 03｜LIVE 执行与权限：G4 机械链，G5 真正生存

## 1. 准备者、控制者、观察者分开

**准备者**只在 PREPARE 阶段创建/还原隔离场景、配置出生点和起始时间并生成初态记录。G4 可以使用预声明小型树木/石面装置；G5 是事先选定、资源附近可合法发现的两处自然场景，不把人造洞和管理员摆好的封口当自然生存。

**控制者**在 ARMED 后只能看到正式 Bot 观察并发语义动作；不持 RCON/token、oracle 通道、写世界命令能力，不读取准备者私有答案。负责开发的 Agent 若同时拥有 Shell，不得在计分期间用 Shell/RCON 临时补位置或材料。使用独立 runner 进程、最小环境和受控启动；列出实际隔离措施。无法落实隔离时报告缺口，不能把一条“不要作弊”注释作为实现。

**观察者**可从独立只读服务端事实核验目标、物品、死亡/在线、过程与终态，但结果只进入验收，不能影响控制者的下一步。失败或 stop 请求可以终止本次计分，不得提供隐藏导航提示继续救活同一次成功。负例注入器只有预先声明的测试权限，独立标记运行，永不计入 G4/G5 成功集合。

ARMED之前形成配置/权限/初态收据；之后任何管理员推进、修改生产代码、调整行为配置或中途换世界都使该次成功声明无效。可以安全停止、保留失败并另开新尝试，但不能回写成功。

## 2. G4：已有连续记录是起点，不是免检

保留现有正常采木、原生 2×2/3×3、工作台、木镐采石、石镐链。首轮仅做一次非计分诊断，连通新采集器和 checker，实际采集 cursor/账本/输入而不是填 true。若源码修复影响该链，诊断优先于长夜。

正式矩阵运行前写定 B01–B05：两次橡木、两次另一树种、一次运行中通过真实事务产生非默认布局。可以用同一对进程和同一真实 session 依次还原场景，但每次开始均独立证明空包和清理完成。不得用重连制造所谓证据独立性。

五次必须在同一最终行为候选、相同批准配置族与固定 runner 版本下连续完整通过。每次从首次受控观察计时不超过 12 分钟；限时在 runner 中实际执行，超时保存部分效果并停止，不仅事后填一个小于720的数。

逐步与终态必须重算：原木来自本次正常挖掘/拾取；原生合成材料扣减与产物入包；工作台精确位置、真实打开与重新打开；木镐实际参与采石并拾取圆石；最终木镐和石镐在 Bob 库存，cursor 空、输入/导航空闲、无未结 unknown。数量允许合法配方整批产出，但不能把额外给物当产出。保护物/组件按实际使用变化核验。

最终候选中任一次失败按原规则保存和诊断；需要修代码/配置/runner 行为就建立新完整集合，不把上一次的成功补进来。仅采集器或 checker 的非行为修正，原始事实足够时可重算，但必须登记实际版本与影响，不静默重命名候选。

## 3. 先做正常入洞／封口小切片，再等夜

在独立非计分装置中，用正常接口复现首格封住后后续 place 失败，明确每一步的站位、支撑面、身体碰撞和命中目标。正常进入不许 tp。修到连续封口和“不可行即停”的正反例都成立，再跑 S01/S02。

不要为了绕过失败一再扩大洞、改变客户端触及距离、让服务器直接设块，或在 G5 期间重新选择管理员已知的安全洞坐标。改测试几何可以用于定位，但只能作为诊断，正式场景必须在最终计分前定版。

## 4. G5：保留原本的 LLM 生存验证，不用固定剧本冒名

S01、S02 事前声明不同的自然地点/场景，可在同一 seed 下的两处或两个事先声明 seed；不强求不同 seed，但不得命令行改 run 名而实际装置完全同一。资源在有界范围内，避免无界探索；选择后不因失败临时换成已知必过地点并删除失败。

Bob 空包开始，正常制作基本工具（本轮默认木镐和石镐）、准备避难、正常走入/封口、完整在线经历自然夜晚至清晨，保有工具并继续一次实际采集。可以有限确定性技能闭环处理点击/寻路；**上层确实由 LLM 使用同一语义接口规划**。把注释写成“LLM 驱动”的固定 Python 顺序脚本，只能算技能测试，不是 S 组。

记录 LLM 实际可见观察、可见动作选择、调用/模型通道标识和语义工具结果即可；不要索取或记录隐藏思维链。无须本轮建设新 Agent Host，复用现有授权宿主；禁止把管理员答案或 oracle 隐藏状态塞给 LLM。验证者据此检查使用的观察来源，不比较私人推理过程。

不睡觉、不登出躲夜、不死亡复活、不 keepInventory、不改时/天气/难度、不清怪/传送/给物。不要求实现战斗新能力；可以选受控难度下附近有自然材料和有限安全地形的场景，但不能关掉原本被要求的生存风险来冒充通过。

持续在线和存活用实际会话、死亡/重生事件、游戏时间及首末状态证明；光靠每隔25秒看到 day_phase 不能排除中间死亡/断线。原始观察缺失时标不确定；既有观测累计计数/事件足够则不必高频截图。

黄昏前记录明确工具基线；清晨比较真实库存及允许的耐久变化。空包、缺关键工具、未结效果不能用“又捡到一块泥土”代替保存进度。正常退出掩体后完成一次合法采集，不能隔墙用旧缓存位置直接挖。

每次建议上限 35 分钟（沿原矩阵），准备足够资源和最小技能后才开始。S01 阻塞不要盲跑同样 S02 浪费完整夜晚；先定位并明确失败，再按预算修复与新候选规则续跑。S01/S02 仍各要最终真实成功，不能以另一个通过豁免。

## 5. 运行结束

结束时出完整结果或明确失败阶段，保留初态/过程/终态和真实时间。通过唯一生命周期入口 stop all；全命名空间核验为零才报全停。未知归属不碰，精确列出 BLOCKED，不影响用户的普通客户端和生产世界。
