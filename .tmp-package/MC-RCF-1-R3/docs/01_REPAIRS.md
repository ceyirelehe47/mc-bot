# 01｜实现修复：保留有效成果，关闭已定位缺口

本页中的“现状”来自 ff29078 独立审查；“必须”是本轮要求。源码路径见 06_SOURCE_MAP。具体回调名称和 Yarn/Fabric 签名由实现者对照实际锁定版本核实，不从文字描述臆造 API。

## A. 进食归因，而不是又一次加长等待（F04）

现状：主包 PICKUP 贯穿已修；生产核心仍用 heldStart-heldNow 产生 claimed，服务端又用同一次库存减少验 claimed。外部移走食物能够让双方数字一致，却不证明正常吃完。

保留每 tick 单阶段、调槽后等待、一次调用一件的语义。增加来自**实际正常消费完成处理**的只读见证，关联 Bob 身份、游戏／控制会话、当前执行、允许食物与组件、手、开始／完成时点和本次消费量。见证不能由客户端自报文案、按键按下、use 开始、isUsing 下降沿或库存减法伪装；钩子只观察正常游戏处理，不手动扣料、恢复饥饿或产出食物效果。只有正常处理的事实及后态相符才能 completed。

外部清物、丢弃、换槽、换手或换会话即使与库存减法完全一致，也不能被归为本次消费。食物效果和饥饿值用于交叉核验，不能单独证明消费；若天然效果、同步延迟或容器余物使核验不确定，保留已发生效果并等待有界对账，不重放可能已完成的进食。先覆盖当前允许的普通食物，已有容器余物支持不得退化；不扩大到新物品系统。

必须实测：正常主包／快捷栏各成功一次且只消费一件；最后一件正常吃完；使用开始后外部移走两件；移走一件并外部恢复饥饿；使用中换手／暂停／取消／断线；正常消费事件与库存同步两种先后顺序；旧消费事件不能复用到下一请求。反例回放必须调用当前真实生产核心与服务端最终核验，不只测旧 Java 探针接口。失败终态再次 tick 不得变成 COMPLETE。

## B. G5 去除特权救场并修正常放置（F03）

移除 `run_survival` 中 armed 后两次 RCON tp，以及任何替代的管理员入洞、预给物资、修墙、清怪、改时逻辑。只有正常 goto、合法采集、原生放置能建立掩体。生产策略不得持有 RCON 凭证或调用 oracle 查询；见 03_RUNBOOK 的权限隔离。

`inside_enclosure` 从实际 Bob 身体位置与可合法获取的局部碰撞／结构事实推导，不得传入计划坐标就设为 true。封闭／头顶实心不能用“不是字符串 passed”或“不是空气”代替。按当前支持的方块碰撞/阻挡性质判断；未知、空回应、权限失败、过期或解析失败返回 unknown。不能将植物、液体、无碰撞装饰视为可靠围护。不要为过夜强做复杂建筑模型，只覆盖本轮实际使用的小型掩体。

先在隔离小场景复现洞内连续放置，采集**实际**身体包围盒、支撑面/命中点、可达站位、交互回执、目标方块和物品减少。优先验证首格封住后是否切断下一次站位/射线、身体是否占目标格、支撑面方向是否正确；这些是排查假设，不是已经确认的根因。修有限站位/支撑面选择和封口顺序，不靠放宽精确目标或服务器 setblock 解决。

小场景至少有：正常走入与连续封口成功；某一步失败且不抛异常不得 sheltered；查询未知／身体不在洞内不得 sheltered。只验证允许的正常玩家动作，不要求任何几何都必须成功，不可达诚实失败即可。小场景通过再等待完整夜晚，避免每次调试先耗一夜。

清晨校验与黄昏前明确的工具/进度快照对比，不使用 `<0 and ...`。两次自然场景均正常做出并保有本轮要求的工具，允许合法使用产生耐久变化；空包、缺关键工具、死亡复活、会话中断或未结 unknown 均不得过。V10 调用实际 G5 策略，另加“误读也不安全”“空包清晨不通过”正反例。

## C. 读路径真正无副作用（F05）

现状：inspect 不再直接 observe，但 tracker.opportunities 仍做服务器世界查询、剔除并写 stale journal。修复不能只删显式调用或改注释。

`inspect_local`、view 与 materialize 使用不可变/有界快照；枚举、分页、排序、格式化不得出生/失效机会、推进任务或追加业务 journal。失效与容量回收在明确写入生命周期/后台 tick 路径完成，保留 durable 回执和崩溃重放语义；先持久化有效状态转换再发布内存结果，避免静默 remove。

后台写入同样不成为远程透视：不可见处发生变化不能自动当作最新可见事实回传 LLM。范围外/遮挡后保留来源明确的旧知识或到期，不远程查询后更新其“现在已消失”。执行准入时可在合法触及和新鲜准星证据下重新核验目标；旧 token/目标替换仍拒绝。

local 的 opportunities 也应用请求 radius、预算、稳定排序和截断说明；不因为它们是历史记录就一次输出整个维度。可见与记忆语义清楚；不得用 omitted_count 泄漏未见隐藏目标。具体字段/上限由 Agent 沿现有有界输出设计，不能无约束增长。

测试：无新帧的受控时段重复查询前后机会生命周期/业务 journal 不变；新鲜合法帧通过显式写路径产生机会；遮挡/范围外变更不更新当前事实；radius 内外非空样本与截断；旧机会失效/容量淘汰/重启不复活旧身份。正常服务器 tick 并行时，用来源/调用追踪分离背景写入与读调用，不能用时间恰好相邻就断言读有写。

## D. stop 核验所有实例，不只是一个 PID（F06）

保留 intent、跨进程锁、真假命名空间隔离、PID+创建时间+标记核验和按角色预算。start/preflight/status/stop 使用同一事实来源。

stop 无论有无 state 记录，都先完整枚举同角色实例；对有明确本轮归属的实例逐一停止，对归属不明者报告 BLOCKED 并保留，不按进程名批杀。停止后必须再枚举，只有目标作用域确为零才能报 STOPPED；一个合法实例已退出而另一个仍在，不能报全停。旧记录存在但指向不同创建时间、PID 被复用或标记不符，禁止误杀。

先用轻量子进程验证：合法记录+额外不同 marker；相同 marker 的多个 PID；无记录孤儿；枚举失败/部分失败；中途某个停止失败；用户无标记进程不受影响。结束回执包含实际范围、剩余数量和未确认实例，不输出完整含秘密的命令行。假环境验证通过才用唯一一套 Minecraft 确认，禁止为了并发验收多开真实游戏。

一角色成功不得清另一角色未结预算；stop、run_id、目录或脚本重启不解除锁定。保持跨进程竞争测试、慢启动、管理器崩溃、状态损坏等已修负例。

## E. 收尾恢复与既有能力回归（承接 R1/R2）

普通成功/失败与显式控制已接入统一收尾，保留；但必须证明**已完成清理**，不能只证明调用了函数。停止导航/业务输入后，cursor 和所有合成格残料要经过当前合法 Screen 的有界恢复及同步确认。一次点击后立刻关屏、只回收一格就宣布全部清理，不能替代验证。恢复债务显式阻止不兼容的新动作，不能仅在日志 warn 后释放成可继续写；也不能用掉落到世界冒充回包。

正常关闭可能由游戏处理余料，必须记录真实去向，不把任何未经证实的实现机制当结论。取消后的恢复点击仅允许已授权清理，不得继续原合成/转移业务；所有清理路径守 Screen ownership 和 session fencing。无容量/失联无法确认就 unknown/恢复债务，不盲点新屏。
