# 04｜阶段顺序、复用与完成判定

## 阶段 0：现场与事实基线

核对 origin HEAD、未提交工作、实际两端进程/加载产物和隔离世界；阻止旧自动重拉，禁止盲目 stop/start。保存本轮起点、现有工作、历史预算、旧 G4 原始记录位置。创建完整覆盖账，先把 I08 BLOCKED、C08 NOT_RUN、旧 G4未充分证明/replay有限重建和 V 缺项准确记录，不能继承整门标题 PASS。

盘点源码权威、installer、上游锁和启动模板。本轮从安全可追溯源码构建，不把旧工作树中的未提交改动当上游。新读取的身份不得泄露凭证；仅缺外部账户轮换不阻断使用安全隔离配置的本地修复，发布前仍不得声称安全事项已完成。

## 阶段 1：两条线在第一次 LIVE 前接通

实现线先修消费归因、生命周期停止、多出口恢复和读路径；验证线先确认字段来自什么实际事件，建立单用例主入口、运行身份和七组历史反例复现。完成离线正反例及假进程故障测试，修好 G5 runner 特权入口。只为本轮需要补观测，不建新通用遥测平台。

首个 LIVE 前，验证者检查：ARMED 控制者无管理员推进能力，必要身份与原始事实真的可记录，业务 checker 不仅解析 reason。至少用受控原生合成/进食正例与等格式变异穿过同一入口，不能等待最后才补采集器。

## 阶段 2：短诊断，不提前宣告整门 PASS

在唯一游戏实例中做一次非计分核心链；做正常入洞与连续放置小切片。允许未完成全部不相关回归时诊断，但权限/安全/本次动作关键负例必须已通过。发现新问题按已定预算修复，保留诊断结果，不把诊断补记成五次计分之一。

## 阶段 3：固定行为候选，完成适用自动化与原子覆盖

候选 C 包含影响游戏行为的 Java、资源、运行 Python 策略/路由、依赖和有效配置。runner/collector/checker 可另外固定版本，但任何行为修改必须说明影响。候选不能只指 JAR 源码，而遗漏 G5 实际策略脚本。

运行当前构建适用的全部测试：JUnit、GameTest、Bridge/Node、installer/lifecycle、Screen/Tom’s、graph/fakeplayer 等相关回归及新增行为测试。旧字符串测试可用等价/更强行为测试替代，必须映射语义并列出发现/失败/跳过；不凑历史数量，不把 `remapJar` 成功当完整测试成功，不将旧45项失败永久白名单化。当前报告475/475只作旧报告，不是本轮门槛或既证事实。

随后逐原子条件重算 C/N/I/A/L/V。原C07可离线验证真实ledger批量/重启；不需为凑数跑上千挖矿。原C08若存在授权普通客户端则自动观察共存；未授权不得自动开用户账号/游戏，保持NOT_RUN，继续其它工作但不能报整轮READY。

上轮L11–L13（孤儿stop、额外实例、跨角色预算）保留并补有记录stop尾部核验变体。I08必须真实转移；V01–V09所谓“同类覆盖”按具体前置、动作、反例后果逐项映射，不能只引用IA25/26。

## 阶段 4：G4五次 → G5两次

固定矩阵和runner版本后按03_RUNBOOK计分。同一候选和配置族，不跨版本补洞、不删失败，不中途开发。G4成立而G5失败，分别记录机械链和生存结果，不能一票抹掉有价值成果，也不能接受总体通过。

## 阶段 5：真正fresh replay与独立验收

从固定上游和C在新空目录经installer生成；新部署目录加载新产物，使用唯一的一套受管实例（先停原实例，不额外并开）；跑完整非计分核心链、关键负例与适用自动化，核验生成源码/资源和加载身份。非计分重放不替代S01/S02。

验证者在不改生产事实的前提下，实际调用最终checker重算本轮所有结论，再跑格式正确的语义变异，检查旧反例只是格式拒绝还是已由真实新格式覆盖。结束检查报告引用的每个文件真实存在且属于被声明的候选。所有缺口精确列出。

## 什么可以复用

| 已有材料 | 处理 |
|---|---|
| 完整、可溯源、语义未改的单项原始事实 | 明确映射后可重算，不机械重做 |
| 原G4只有chain true/截断回执/假session标签 | 作为诊断进展保留；缺证据部分重跑 |
| 修改后候选的正式五次核心链 | 需要该候选连续五次，不跨候选拼接 |
| 新目录复制旧build树的成功日志 | 保留为有限重建成功，不能命名fresh replay |
| 历史合成反例/Java纯核心观察 | 复现审查用，永不计LIVE成功 |
| 只改checker／报告且原始事实完整 | 可离线重算；登记旧新版本与结果，不篡改原始记录 |

整体只有三种交付状态：READY_FOR_REVIEW、PARTIAL、BLOCKED。PASS只用于子门满足全部子条件的场景；“PASS(1缺口)”不得再出现。预算用完不改验收，写出下一最小复现命令、准确停点与安全停机结果。
