## 真正实现了什么

### Java 控制核心

`BridgeKernel` 是一个单身体协调器。HTTP 工作线程只能接受请求、读缓存、读事件，所有 `BodyBackend` 调用都发生在 `tick()` 所在游戏线程。控制租约、请求幂等、执行状态和事件不放在 DSH 插件里。

操作先写入并同步持久回执，随后才在游戏线程启动。相同请求标识与相同参数返回原回执，不重复启动；同一标识换参数会拒绝。排队命令也绑定接纳时的租约代次，不能被同一 owner 的新租约复活。重复认领有效租约必须出示原控制令牌，不能只报同一 owner 字符串。

控制请求绑定具体 execution id；旧取消命令不能取消后来启动的任务。暂停、恢复、取消复用 AIBot 现有 IntentController / TaskManager。对任务的观察保留原 Task 对象，不使用全局最后一个任务的终态冒充原任务完成，因此安全任务结束不会被视为采集完成。

控制租约为 30 秒，DSH 每 10 秒续租；释放或失效在下一游戏 tick 暂停普通工作，不恢复旧大脑。安全控制仍由 AIBot 处理。没有服务器 tick 时不可能保证身体在真实时间内完成暂停，状态会暴露快照过期。

### 存储、重启与未知结果

`BridgeJournal` 是本地单写者、带长度和 CRC 的帧日志，写入后同步，文件互斥锁防第二个写者。完整损坏帧拒绝加载；不完整的末尾帧回退到最后一个已验证帧。CRC 是损坏检测，不是防篡改认证。

日志位于世界存档下 `aibot/external-body-<bot名小写>.journal`。默认最大 32 MiB；最多接受 1024 个执行和 2048 个控制记录；向客户端提供最后 4096 个事件的重放窗口。达到容量后失败关闭，不自动删记录以腾空间。**这版是有限试玩切片，不是无限期运行服务。**

重启后未完成执行变成 `outcome_unknown`，未处理控制变成拒绝，不自动重放世界副作用。客户端必须重新观察后显式决定下一步。不同身体 UUID 也会触发对账和控制权失效。服务停止先暂停、记录未知，再清理外部工作；不会把这一版描述成可跨重启无缝恢复任意 Task。

### HTTP 与事件

只监听 `127.0.0.1`，Bearer 密钥为 32～256 位 URL-safe 字符；拒绝带 Origin 的浏览器请求，没有 CORS。请求体、响应、线程数、排队数、事件读取者数量都有界。密钥与租约令牌不进入模型工具结果和事件日志。

第一版采用 **HTTP 命令 + 独立长轮询事件读取协程**，没有 WebSocket。选择理由是减少依赖；这不是让模型调用 `get_events` 一直等待。DSH 模型回合结束后，普通进程级事件读取仍继续，且不会阻塞动作请求。通知缺口显式返回 gap，需要读取快照；快照不能替代丢失的事故历史。

执行异常不等于动作回滚。Node 客户端不自动重试变更请求；丢失回执返回 `outcome_unknown` 和 request id，阻止直接以新 id 重发。通过 `mc_request_status` 查找原回执。查不到时仍不能证明旧请求从未到达；M0 没有交互式同 id 重试工具，保持暂停排查，不绕过这个保护。

### Minecraft 接缝

补丁脚本修改十个冻结的上游文件，逐个核验 Git blob id 和锚点数量，全部验证通过后才写文件。新增九个 Java 文件。现有目标任务、安全任务、寻路等实现没有重写。

切口包括：旧 Brain 的消息入口、续推理、异步响应；自动领任务；通用 Task 分配；Goal tick；旧工具处理器；Intent 控制；公共授权门和面板命令；启动、tick、死亡、停止钩子。保留原授权后，游戏内 `@Bot` 与面板聊天可转交 DSH；旧面板动作、库存变更、传送和其他管理入口被拒绝。服务器管理员仍能通过原版命令或其他模组改变世界，这不属于桥接租约能防止的范围。

感知提供身体状态、背包、上游 PerceptionSnapshot、当前任务和安全状态。广域感知每 10 tick 更新一次并附带感知年龄；任务状态和生命变化仍持续采集。性能效果尚待实机测量。

死亡只记录上游可获得的最近伤害来源、坐标、维度和当前执行。没有完整伤害因果链，不宣称能证明“苦力怕炸飞后摔死”的全部过程。

### 八个有界动作

`goto`、`gather`、`craft`、`smelt`、`eat`、`set_base`、`deposit`、`say`。

`gather` 的 count 是最终背包配额，完成时额外检查；`goto` 检查到达目标三格以内。上游 MoveTask 会在寻路失败后挖掘，因此要求显式 `allow_terrain_changes=true`，距离限制 128 格。

其他任务的完成只表示上游 Task 完成，外部 Agent 应再观察验证用户目标。工作台等功能方块可能被复用，不保证每次 craft 都额外产出指定数量。沿用原版 Task 也不等于证明所有行为都严格符合人类客户端操作方式。

`say` 只写 AIBot 面板，不是全服聊天；它暂时占用单执行槽。成功 say 不唤醒新回合，避免“回复完成 → 再回复”的循环。该版本没有高层 `achieve_goal`、自动钻石链、战斗或建筑工具。不能把“会接外部 Agent”宣传成“已经能自主获得全套铁装”。

### DSH 插件

原生入口 `src/index.ts` 通过公开 `ctx.tools.register(defineTool(...))` 注册 16 个工具；输出使用真实 DSH 支持的 `{type:'json'}` canonical value，不把执行标识藏在自然语言里。

插件绑定调用工具的实际 Agent 实例，其他会话不能接管。租约和 HTTP 生命周期附着于 Agent scope；不是附着于一次短工具调用。已接受的普通长任务调用 `exec.concludeTurn()` 结束当前模型回合，由后续事件推进，而不是让模型不停查询进度。

普通进度不唤醒。终态、严重伤害、死亡、游戏消息、安全抢占和控制丢失按策略进入公开 `inject` / `steer`（MC-2A0.1F：Body 事件传输禁用 `followup`——忙碌普通事件 `inject` 同回合可见，空闲可唤醒终态 `steer` 续作，紧急事件一律 `steer`）；用户暂停或取消后，通知仅 `inject`，不自动发起后续工作。

**入队不是落盘。** 事件入队后等待 `ctx.sessionPersistence.flush()` 成功，再保存消费位置。插件要求持久会话；不存在对应存储时拒绝连接。该公开 API 已在冻结 DSH 源码核验，但真实 DSH JSONL 后端的组装和崩溃实验还没跑。

仍允许崩溃边界上的重复通知；事件携带 epoch/sequence，模型被要求先对账。它不是跨 Minecraft 与 DSH 的分布式 exactly-once 事务，不能保证所有可能的端到端动作重复都自动消除。

## 仍需接手者验证或修补

1. 用真实上游 checkout 执行补丁验证、编译九个 Java 文件，确认真实类路径、方法签名和钩子顺序。
2. 用真实冻结 DSH 加载插件，验证工具参数、canonical JSON、concludeTurn、scope disposal 和落盘 barrier。
3. 游戏测试新世界/新 Bot，先完成木头—木板/木镐的小链，再扩任务。
4. **恢复旧存档中的活动 Mission/Task 是已知未验证边界。** 新分配护栏可能拒绝上游恢复中的 assignSilently。不能直接把本包安装到重要旧世界；先用无未完成 Mission 的隔离存档。正式迁移需要单独审计恢复入口，而不是关掉护栏。
5. 值得后续补充：同 id 的显式未知请求重试、日志轮换/配额治理、更多身体能力、完整事故链、真正的长跑与资源消耗证据。
